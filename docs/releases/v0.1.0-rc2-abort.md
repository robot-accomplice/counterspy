# ABORT Review — Publish counterspy v0.1.0-rc2 as a public sudo quarantine tool

**Reversibility & blast radius:** The *release* is revertible (a tag). The *impact* is not
symmetric by audience. **Personal / trusted-developer use:** blast radius = your own
machine, fully reversible via `restore` — low. **Public release under sudo on strangers'
Macs:** a false positive or an adversarial-input failure runs as **root** on a machine the
maintainer never sees; a mistaken quarantine can break a user's software, and (per the
findings below) `restore` does not fully reverse a disabled launch job. High, one-way at
the point of user impact.

**Decision under review:** Publish `counterspy` v0.1.0-rc2 (commit `1fd121c`) as a public
tool that, under sudo, quarantines user-selected persistence/process items on third
parties' Macs.

**Mechanical gates (cited, not assumed):** `go test ./...` PASS · `go vet` clean ·
`gofmt` clean · `architext validate` passed. ABORT is judgment layered on top; the gates
are green and do not resolve the issues below.

---

## A — Premortem (assume failure)

> We shipped v0.1.0-rc2 publicly, and it failed because a non-developer ran it on an
> ordinary Mac, saw legitimate Developer-ID software — VPN helper, backup agent,
> auto-updater, even their EDR — flagged **Quarantine/Investigate**, and either
> quarantined something load-bearing (breaking it, and `restore` didn't fully bring it
> back), or drowned in scary flags and dismissed a real detection. The ignored warning
> sign: we measured the false-positive rate on exactly one machine — a developer's.

**The one sentence that stops the ship:** *"We have not measured the false-positive rate
on a single machine that isn't a developer's."*

---

## B — Red team station verdicts (verbatim, unaveraged)

1. **Attacker / Competitor — NO-GO** — a hostile local actor can win a `stat`/`rename`
   TOCTOU race to make the root-privileged Quarantine/Restore move or overwrite an
   arbitrary file (no `Lstat`/`EvalSymlinks` anywhere); and the tool will confidently
   recommend quarantining legitimate EDR/AV/MDM because the allowlist is Apple-only.
   Also: ANSI/prompt injection via attacker-controlled plist `Label`; no subprocess
   timeouts (plist-bomb DoS); world-readable unauthenticated `manifest.json`.
2. **Worst-Case Customer — GO-WITH-CONDITIONS** — restore is not discoverable after a
   quarantine (no undo command printed); combined with scary category names and FP
   volume, a panicking non-expert breaks their own app with a high-friction recovery.
3. **Resource Auditor — NO-GO** — false-positive volume unvalidated on real (non-dev)
   Macs; detection scope is narrow (misses signed/kernel/firmware); no telemetry to
   learn the field FP rate; unbounded codesign fan-out is slow at scale.
   *(Correction by the review board: this station also claimed "8 unresolved CRIT bugs."
   Verified against current source — all 8 are FIXED with passing regression tests
   [Key-collision, tripwire-ordering, spctl exit-code gate, plist key/value, PID-only
   identity, TCC fail-loud, clobber-proof dest, actor allowlist refusal]. The station
   read the `.swarm` findings LOG as live state. Its FP verdict stands; the bug claim
   does not.)*
4. **Future-Me (6 months) — NO-GO** — `manifest.json` (the designated undo + RCA trail)
   omits the tool version AND the score/tripwire/recommendation that justified each move,
   and detection policy is compiled-in with no tuning path — a future "why did it
   quarantine X" is un-RCA-able and un-fixable without shipping a new binary. (Praised
   the actor's safety engineering as "unusually rigorous.")
5. **Domain / Integrity — NO-GO** — `restore` never re-issues `launchctl bootstrap`, so
   restoring a false-positive on a load-bearing LaunchDaemon leaves files back but the
   **service still dead** ("reversible" is materially overstated); score-only escalation
   (≥HighTier) quarantines benign `persistence-only` items with zero malicious signal; no
   xattr/ownership/cross-volume preservation; `bootout` bypasses the protected-path check.

**Tally: 4 NO-GO, 1 GO-WITH-CONDITIONS.**

### Root-cause clusters

- **C1 — The tool assumes a cooperative filesystem, but it runs as root while hunting
  malware that is *already present*.** Leverage: canonicalize + `Lstat`/`O_NOFOLLOW` every
  path at act-time, integrity-protect + `0600` the manifest, sanitize all
  attacker-derived strings before terminal output, bound every subprocess.
- **C2 — "Reversible" means files-back, not system-restored.** Leverage: re-`bootstrap`
  on restore (or stop claiming a bootout is reversible); preserve metadata; handle `EXDEV`.
- **C3 — Fitness for the stated audience is unvalidated (the premortem).** Leverage:
  measure FP on a representative set of non-developer Macs AND expand the allowlist to
  Gatekeeper-accepted Developer-ID; soften the score-only escalation.
- **C4 — Un-diagnosable and un-tunable in the field.** Leverage: stamp tool version +
  the score/tripwire/recommendation into the manifest; add an out-of-band tuning surface.
- **C5 — The "human decides" safety model needs the human able to undo and not panic.**
  Leverage: print the exact `restore` command after every quarantine; explain categories.

### The one fix (neutralizes the highest-risk cluster, C3)

**Measure the false-positive rate on a representative set of non-developer Macs, and
expand the allowlist to Gatekeeper-accepted Developer-ID software.** This single change
neutralizes failure modes 3, 4, 5 (and softens 13) at once — the tool stops flagging
legitimate signed software, and the ship decision rests on data instead of a one-machine
guess. (It does not, by itself, resolve C1 or C2 — those are independent blockers.)

### Acceptable risks (monitor/document, do not block)

- **#14 `bootout` bypasses `isProtected`** — SIP prevents real damage to genuine
  `/System` daemons and bootout is best-effort; cheap to add, document for now.
- **#15 no xattr/cross-volume** — fails loud (`EXDEV` errors, no data loss); document
  "same-volume artifacts" and defer.
- **#13 narrow detection** — a *documented non-goal*, not a defect; the fix is clearer
  "first-pass triage, not your only defense" messaging in README/report, not code.
- **#12 codesign fan-out perf** — acceptable on personal machines; optimize (Rule 15:
  last) only after correctness.

### Dealbreaker

**YES — two independent ones for a *public* release:** (1) the root-privileged symlink
TOCTOU (arbitrary file move as root under adversarial input, C1), and (2) the unvalidated
false-positive rate on real users combined with an allowlist that flags legitimate signed
software including security products (C3). Either alone blocks a public ship; both are
code-verified.

## T — Go / No-Go poll

- **Confidence: 9/10** that this is **NO-GO for a public release** (blocking issues are
  real and verified against source, not plausibility).
- **Blocking issue (one line):** A root tool that, under adversarial input, can be raced
  into moving an arbitrary file — and that will confidently recommend quarantining
  legitimate signed software (incl. EDR) at an FP rate never measured off a dev machine.
- **What would move the score:** the convertibility conditions below — chiefly a measured
  FP rate on diverse non-dev Macs and the C1/C2 hardening.
- **Station verdicts:** Attacker NO-GO · Worst-Case Customer GO-WITH-CONDITIONS · Resource
  Auditor NO-GO · Future-Me NO-GO · Domain/Integrity NO-GO.

### FINAL VERDICT

- **Public release: NO-GO.**
- **Personal / trusted-developer (internal, beta) use: GO** — the reversibility engineering
  is genuinely rigorous, the blast radius is your own reversible machine, and an expert
  can discover and use `restore`. Ship it to yourself and vetted testers now.

### Convertibility conditions (NO-GO → public GO)

1. **C1 — Harden against a hostile filesystem:** canonicalize + `Lstat`/`O_NOFOLLOW` on
   every act-time path (kill the TOCTOU); sanitize attacker-derived strings before
   terminal output; write `manifest.json` `0600` with an integrity check; add subprocess
   timeouts + input size caps.
2. **C2 — Make reversibility whole:** `restore` re-`bootstrap`s booted-out jobs (or the
   docs stop promising a bootout is reversible); preserve metadata; handle `EXDEV`.
3. **C3 — Validate fitness (the one fix):** measure the FP rate on ≥10 diverse
   non-developer Macs; expand the allowlist to Gatekeeper-accepted Developer-ID; soften
   the score-only Quarantine escalation. Target a documented, acceptable FP rate before
   public ship.
4. **C4 — Make it diagnosable/tunable:** stamp tool version + score/tripwire/recommendation
   into the manifest; add an out-of-band tuning surface (config/rules file).
5. **C5 — UX safety:** print the exact `restore` command after every quarantine; explain
   category names; clarify the sudo/TCC requirement.

**Project-lead summary:** The engineering is strong and the safety *intent* is right, but
v0.1.0-rc2 is a root-privileged tool validated on a single developer's machine with an
open adversarial-hardening gap and an incomplete reversibility guarantee — **ship it to
yourself and vetted testers now, and treat public release as blocked until the five
conditions are met.**
