## A — Premortem (assume it failed)

We opened the PR and it failed because `develop` received a half-built Phase 2.5 whose green checks masked three separate problems: (1) the headline capability — see decrypted traffic in the console — was wired to a `nil` channel with no reader and no view, so it displayed nothing while the CLI told users to run `console --intercept=…`, a flag that no longer exists; (2) the secret masker silently missed the most common token shapes, persisting `refresh_token` / `id_token` values in cleartext to the 0600 log; and (3) a deadlock in the per-message pump — introduced by the very fix that was supposed to make it correct — could hang a forwarded connection. Green `-race` tests were read as "it works."

**The one sentence that would have stopped the ship:** *"Green tests prove the pieces compile and the happy path parses — they do not prove the feature is wired, the secrets are masked, or the pump can't hang; run it and read the masker."*

## B — Red Team Findings (five independent stations, verbatim verdicts)

1. **Attacker / Security — GO-WITH-CONDITIONS.** Blocking: `Redact` compound-name bypass (`internal/model/inspect.go:65`) — `refresh_token`/`id_token`/`authToken` and kin leak in cleartext to the 0600 log and the socket; the advertised "no sink ever sees a raw secret" invariant is currently false. (MITM primitive itself sound: P256, trust scoped `-p ssl`, key 0600, upstream verified, no `InsecureSkipVerify`.)
2. **Worst-Case Customer — GO-WITH-CONDITIONS.** Blocking: the product ships user-facing instructions pointing at `console --intercept=…`, but ingestion is a `nil` channel with no socket/log reader and no view renders captured messages — the headline decrypt output is a silent no-op with no honest empty state. (For a prod release this station would be NO-GO.)
3. **Resource Auditor — NO-GO.** Blocking: the intercept→console path is not wired (`main.go:553` passes `nil`; `runConsole` never parses `--intercept`), so the merge dumps a skeleton that compiles, passes tests, and displays nothing live while telling users to run a flag that doesn't exist.
4. **Future Maintainer — GO-WITH-CONDITIONS.** Blocking: branch ships an "Exfiltration merge" wired to a `nil` channel and rendered nowhere while `flows.json` still says "InterceptedFlow" and `roadmap.json` still describes the disproven pf mechanism, with no record of open Tasks 8–10 — fix the flow/roadmap staleness and record the open work in Architext (or state the inert path + open tasks explicitly in the PR body).
5. **Domain / Integrity — GO-WITH-CONDITIONS.** Blocking: the `copyTee` unbuffered-pipe tee + blocking `popQueue` can permanently deadlock `runRelay` and freeze a forwarded connection when a server emits an unmatched response (`pump.go:241/349/221`); the tee write needs a deadline / non-blocking drop and `popQueue`'s wait must be bounded before this is correct against its own "no deadlock / never affects traffic" claims.

**Vote tally:** 1 NO-GO, 4 GO-WITH-CONDITIONS — but two of the conditions are genuine live defects (L1 secret leak, F1 deadlock), not mere incompleteness.

### Root-cause clusters

- **A — "Feature wired to nothing"** (W1, Self1): the Exfiltration merge is a plumbing skeleton; producer works, consumer/render/self-exclusion don't exist. Leverage point: complete ingestion + render + self-exclusion, **or** explicitly mark the PR WIP and gate the "view via console" guidance.
- **B — "The security promise is false"** (L1, Sock1): masking and sink-confidentiality don't hold. Leverage point: fix the `Redact` denylist and lock socket perms. **L1 is live now.**
- **C — "Pump concurrency correctness"** (F1, M1): the just-applied correlation fix traded a message-drop race for a deadlock and still drops silently on abort paths. Leverage point: bound `popQueue`'s wait / make the tee non-blocking.
- **D — "Model drift"** (D1): Architext flow + roadmap contradict the code and the recorded decisions.
- **E — "Residual trust safety"** (S1): teardown is well-built for catchable exits but not crashes; unconditional untrust-when-CA-exists closes it.

### The one fix (highest-risk cluster = B)

**Fix the `Redact` body-secret matcher** so compound and camelCase token names are masked (align body masking with the header path, which already handles `*-token`), and add a test asserting `refresh_token`/`id_token`/`authToken` values never reach a sink. This neutralizes the only failure mode that leaks live to disk today. **Necessary, not sufficient** — it does not make the branch shippable; W1 and F1 remain.

### Acceptable risks (do not block a *clearly-labeled WIP* PR; must be fixed before "feature done")

- **S1** — teardown is genuinely careful for catchable exits; crash-residual is recoverable via the printed `--uninstall`. Monitor; consider unconditional untrust. *Why deferred:* real but low-likelihood, self-healing remedy exists.
- **Sock1 / h2** — narrow trigger conditions (non-default umask; fragmented ClientHello on strict-h2 clients). *Why deferred:* low likelihood, no data-loss, fixable independently.
- **M1** — instrumentation debt; matters for field RCA but not for a review branch. *Why deferred:* observability improvement, not a correctness blocker, and partly subsumed by fixing F1.

### Dealbreaker

**YES.** For a PR intended to **merge Phase 2.5 into `develop` as done**, three independent blockers stand: a live secret leak (L1), a confirmed deadlock regression (F1), and a fundamentally unwired headline feature (W1). Two are genuine defects that should be fixed regardless of Phase 2.5 completion.
